# 재미 개선 아이디어 (미착수)

구현하지 않은 제안 모음. **이미 있는 자산으로 싸게 되는 것**을 위에 뒀다.
"드는 힘"은 기존 코드 재사용 정도 기준.

---

## A. 거의 공짜 — 이미 만들어둔 걸 노출만 하면 됨

### A1. 끝말잇기 완성해서 연결 ⭐
`WordChainGame.tsx`(265줄) + `wordchain.ts` + `wordchain-dict.ts`가 **이미 다 있는데
App.tsx에 연결이 안 돼 있다.** 완성 판정만 끝내면 게임 하나가 즉시 늘어난다.
설득게임이 아이콘이 없어서 1년 가까이 아무도 못 들어간 전례가 있으니(이번에 고침),
"만들어놓고 안 붙인 것"은 우선순위를 높게 볼 만하다.
- 드는 힘: 완성도 확인 + 아이콘 1개 + 분기 6줄

### A2. 오목 훈수 버튼
엔진이 이미 최선수를 계산한다(`chooseAiMove`). 사람 차례에 `'진심'` 난이도로 한 번 돌려
그 자리를 반짝이면 끝. 캐릭터가 "여기 어때?" 하고 훈수 두는 연출로 성격도 살릴 수 있다.
- 드는 힘: 버튼 1개 + 기존 함수 호출 + 하이라이트 CSS

### A3. 초텐 vs 아메 자동 대국 (어트랙트 화면)
오목 엔진은 양쪽 다 AI로 돌릴 수 있다(자기대국 테스트에서 이미 하고 있다).
아무도 안 할 때 데스크탑 배경에서 둘이 알아서 두게 두면 캐릭터 대사가 계속 흐른다.
- 드는 힘: 기존 자기대국 루프 + 대사 훅 재사용

### A4. 관전 모드
오목·홀덤 멀티는 방 목록이 이미 공개고, 오목은 착수가 **공개 테이블**이라
관전이 사실상 공짜다(읽기만 하면 됨). 홀덤은 손패만 가리면 된다.
- 드는 힘: 오목은 매우 낮음 / 홀덤은 중간

### A5. 퀴즈 오답노트
`answerBank`에 실패 데이터가 이미 쌓이고 있고 `getChronicFailures`도 있다.
"내가 자주 틀린 것" 화면으로 보여주기만 하면 된다.
- 드는 힘: 조회 화면 1개

## B. 리텐션 — 다시 오게 만드는 것

### B1. 캐릭터 호감도 (메타 진행) ⭐⭐
지금은 게임을 아무리 해도 **남는 게 없다.** 초텐쨩은 첫날이나 100일째나 똑같은 말투로
똑같은 대사를 한다. 이 프로젝트 최대 자산이 캐릭터인데 그걸 성장 축으로 안 쓰고 있다.

**핵심: 두 캐릭터를 따로 쌓는다.** 초텐쨩/아메 호감도를 각각 관리하면 지금은 아무 의미
없는 **변신 버튼이 선택**이 된다 — 오늘 누구랑 놀지 고르는 것 자체가 게임이 된다.

그리고 한쪽만 계속 하면 **다른 쪽이 알아챈다**(form별 `last_played_at` 하나면 됨):
- 초텐쨩: "요즘 나랑 안 놀아주네…? 아메랑만 놀지? 삐졌어!! …아니 안 삐졌어."
- 아메: "…오랜만이네. 딱히 기다린 건 아니야."

성격이 정반대라 같은 상황에서 반응이 완전히 달라진다 — 질투 연출이 공짜로 나온다.

**해금 대상 (우선순위 순)**
1. **대사 티어** — `mascotLines.ts`가 이미 `LineKind`별 배열에서 뽑는 구조라, 호감도
   단계만 얹으면 같은 상황에서 더 친밀한 배열을 고르게 된다. 코드는 거의 안 늘고
   **대사 쓰는 일**이 대부분 → LLM 비용 0원. 아메는 츤이 서서히 벗겨지는 게 보상이 된다
   (지금 `ame_dere` 이미지가 거의 안 쓰이는데 이게 쓰임새가 생김).
2. **복장/표정** — 아래 E1 파이프라인으로 생성 (산타·유카타·교복 등)
3. **배경** — `public/back/` 이미 캐릭터별로 있음

**붙일 자리는 이미 다 있다**: 각 게임 종료 지점이 전부 마스코트 이벤트로 잡혀 있다
(`omok_win`, `mp_win`, `soup_solve`, 설득 항복). 게이지 UI도 `.persuade-gauge-*` CSS가
아메 다크모드까지 만들어져 있어 그대로 쓰면 된다. **새로 만들 건 테이블 1개 + RPC 1개.**

- 드는 힘: 중간 (코드는 작고, 대사 쓰는 분량이 큼)
- ⚠ 지킬 것 ①: **칩·크레딧과 엮지 말 것.** 호감도를 크레딧으로 사거나 호감도가 칩을 주면
  겜블링 경계(ARCHITECTURE.md)를 건드린다. 순수하게 대사·외형만.
- ⚠ 지킬 것 ②: **이겨야만 주면 안 된다.** 플레이하면 기본 지급 + 승리 보너스.
  안 그러면 초보가 계속 지면서 아무것도 못 받는다.

### B2. 일일 미션 / 연속 접속
"오늘 오목 1승", "퀴즈 3문제" 같은 가벼운 목표 + 크레딧 소량 보상.
크레딧 경제가 이미 있어서 붙이기 쉽다.
- 드는 힘: 테이블 1개 + 판정 RPC

### B3. 통합 전적/랭킹 화면
`quiz_results`·`ranking` 테이블은 있는데 홀덤·오목 전적은 안 남는다.
게임별 전적을 한 화면에 모으면 "얼마나 했는지"가 보인다.
- 드는 힘: 각 게임 결과 저장 + 통합 조회 화면

## C. 멀티 살리기

### C1. 초대 링크 미리보기(OG 태그) ⭐
초대 링크를 카톡에 붙여도 **그냥 URL 텍스트로만 뜬다.** OG 태그를 넣으면 캐릭터 썸네일 +
"OO님이 오목에 초대했어요" 카드가 뜬다. 클릭률이 눈에 띄게 달라지는 부분.
- 드는 힘: 정적 OG 태그는 매우 낮음. 방별 동적 카드는 서버 라우트 필요(Vercel 함수)

### C2. "지금 접속 중" 표시
퀴즈 로비엔 Presence가 이미 붙어 있다(`mp:lobby`). 같은 걸 홀덤·오목 로비에도 붙이고,
데스크탑 화면에 "지금 3명 접속 중"을 띄우면 빈 로비의 쓸쓸함이 줄어든다.
- 드는 힘: 기존 Presence 코드 복사 수준

### C3. 빠른 대전 버튼
방 목록을 보여주는 대신 "바로 시작" 하나로 빈 방에 넣거나 새로 만들어준다.
사람이 적을 땐 봇을 자동으로 채운다(봇 인프라는 이미 있음).
- 드는 힘: 낮음

## D. 감각 / 완성도

### D1. 사운드 & BGM
지금 **완전 무음**이다. 착수음·정답음·칩 소리만 있어도 체감 완성도가 크게 오른다.
`choten-sound` 저장소가 따로 있으니 자산을 가져올 여지도 있다.
- 드는 힘: 낮음 (단, 음소거 토글은 필수)

### D2. 오목 무르기 / 기보 리플레이
싱글에 무르기가 없다. 착수 기록은 이미 `moves` 배열로 다 갖고 있어서 되돌리기는 쉽다.
멀티는 기보가 DB에 남으니 끝난 판을 다시 돌려보는 것도 된다.
- 드는 힘: 싱글 무르기는 낮음 / 리플레이는 중간

### D3. 적응형 난이도
연승하면 슬쩍 올리고 연패하면 내린다. 난이도 파라미터가 이미 표로 정리돼 있어서
그 사이를 오가기만 하면 된다.
- 드는 힘: 낮음

### D4. 전용 아이콘 정리
설득게임은 지금 캐릭터 초상을 아이콘으로 쓰고 있다(전용 아이콘 없음).
게임이 늘수록 아이콘 톤이 안 맞으면 데스크탑이 지저분해진다.
- 드는 힘: 그림 작업

## E. 캐릭터 이미지 파이프라인 (도구는 이미 만들어둠)

### E1. `tools/gen-char.mjs` + `tools/cutout.mjs` ✅ 동작 확인됨
복장·포즈·표정 변형을 매번 외부 툴로 손수 만들던 걸 자동화했다. 산타 초텐/아메로 검증 완료.

```bash
GEMINI_API_KEY=... node tools/gen-char.mjs --char choten --name santa \
  --chroma blue --prompt "빨간 산타 원피스, 산타 모자, 검은 벨트" --n 4
node tools/cutout.mjs tmp/gen/choten_santa_1.png --out public/char/choten_santa.png
```

**일관성의 핵심은 프롬프트가 아니라 레퍼런스 이미지다.** 기존 PNG를 같이 넣어야
리본 개수·허벅지 하트·통굽 구두 같은 디테일이 안 흔들린다. 텍스트로만 설명하면 반드시 드리프트한다.

**실제로 겪은 함정 (다시 밟지 말 것)**
| 증상 | 원인 | 대응 |
|---|---|---|
| 모자 끝이 잘림 | 레퍼런스가 화면에 꽉 차 있어 모델이 그 프레이밍을 따라함 | 프롬프트에 "위아래 10% 여백" 명시 |
| 아메가 담배를 들고 나옴 | 레퍼런스로 `ame_smoking.png`를 씀 | 소품 없는 이미지만 레퍼런스로 |
| 민트 머리카락이 지워짐 | 배경이 연한 민트로 나와 머리색과 겹침 | 초텐=마젠타/파랑 크로마 |
| 빨간 옷에 구멍 | 마젠타 배경 ↔ 빨간 산타옷이 가까움 | `--chroma blue` 로 교체 |

→ **크로마 색은 캐릭터 고정 팔레트뿐 아니라 그때 입히는 의상 색과도 멀어야 한다.**
배경 제거는 색이 아니라 **연결성(flood fill)** 기준이라 아메의 검은 머리·검정 치마가 살아남는다.

**비용**: 1장당 출력 1,290토큰 고정 → 약 **55~60원**. 후보 4장 뽑아도 250원 수준.

**런타임에서 생성하지 말 것.** 볼 때마다 과금 + 몇 초 지연 + 사람마다 다른 그림이 나온다.
개발 때 후보를 뽑아 사람이 고르고 `public/char/`에 커밋하는 자산 파이프라인으로만 쓴다.

### E2. 다음 단계 (필요해지면)
- 복장이 수십 벌로 늘면 **LoRA 학습**(Replicate/fal)이 일관성·단가 모두 유리해진다
- 표정만 바꾸는 변형은 **얼굴 레이어 분리**가 훨씬 싸다 — 지금 원화도 표정별로 몸이
  동일한데 전신을 매번 다시 그리고 있다. 몸 N벌 × 얼굴 M개 = N+M 자산으로 줄어든다

## 우선순위 제안

1. **A1 끝말잇기 연결** — 이미 만든 게임을 못 쓰고 있는 상태 해소
2. **B1 캐릭터 호감도** — 모든 게임을 하나로 묶는 유일한 축, 이 IP의 강점과 직결
3. **C1 초대 링크 OG** — 이번에 만든 초대 기능의 효과를 몇 배로 키움
4. **D1 사운드** — 투자 대비 체감 완성도 상승폭이 가장 큼
